# AI 辅助科研

!!! abstract "一句话"
    AI 可以**解释**，但不能替你承担**判断责任**。
    它的价值是降低技术细节的进入成本，而不是替你产生创新。

## 1. AI 读论文

不要只问"总结全文"。给 AI 一个固定提示词，让它按你训练的阅读框架回答：

```text
不要总结全文。请回答：
1. 研究对象是什么？
2. 作者发现/解决的具体问题是什么？
3. 方法是什么？
4. 真正的贡献在哪里？
5. 用什么证据支撑？
6. 哪些问题摘要无法回答，需要读正文？
```

!!! tip "与阅读框架统一"
    这六个问题正好对应 [第7–8计](../ch2-duwen/index.md) 的论文阅读框架：
    先抓对象、问题、方法、贡献、证据，再决定读多深。

进一步追问时，可以问：

- 威胁模型 / 假设是什么？
- 这条 claim 被哪张图、哪段实验支持？
- 与某个 baseline 的**实质差异**是什么？
- 某个公式承担什么功能？
- 哪些信息摘要里没有、必须读正文？

## 2. AI 辅助代码

### 适合交给 AI

- 解释陌生代码 / 库的用法
- 写实验脚本初稿、数据处理脚本
- 查报错信息、定位常见问题
- 改绘图代码、调参数

### 不能直接接受 AI 的结论

!!! danger "红线"
    以下判断必须由人完成，不能直接接受 AI 的回答：

    - "实验已经证明……"这类**因果/结论性断言**
    - benchmark 是否**公平**、是否有偏差
    - 算法在理论上是否**正确**
    - 安全机制是否**真正成立**（尤其是密码学/安全方向）
    - 任何要写进论文的**数字与结论**

> AI 帮你把代码跑起来；**跑出来意味着什么**，要你自己判断。

## 3. AI 辅助写作

!!! quote "原则"
    AI 可以帮你**把话说清楚**，但不能帮你**制造贡献**。

- 可以让 AI 润色表达、调整句式、检查语法。
- 不能让 AI 替你"想出"贡献、替你编造证据、替你想不出来的部分硬写。
- 写不出来的地方，往往说明你还没想清楚——那是科研本身的问题，不是写作问题。

!!! warning "学术诚信"
    使用 AI 辅助写作时，须遵守课题组与目标期刊的披露要求；
    核心观点、实验结果、结论必须由人负责，不得把 AI 输出当作自己的判断直接提交。

## 4. AI Agent / Coding Agent

2026 年，AI 不只是"问答"，而是可以作为 **agent** 在本地工程里跑代码、改文件。
课题组常用的组合示例：

| 工具 | 定位 |
| --- | --- |
| **VS Code** | 主 IDE，统一编辑与运行 |
| **Ollama + 本地 Qwen** | 本地大模型，处理不敏感、离线或私有数据 |
| **OpenCode / Codex 等 coding agent** | 在工程内跑多步任务、改文件、跑命令 |

!!! note "本地模型的价值"
    对**敏感数据、未公开代码、组内私有信息**，优先用本地模型（Ollama + Qwen），
    避免把数据发送到第三方云服务。

!!! danger "Agent 的红线"
    让 coding agent 自动改文件前，必须：
    1. 确认改动范围；2. 跑测试/复现；3. 自己看懂每一处改动。
    agent 产出的代码同样适用上面"AI 辅助代码"的红线。

## 防幻觉：定位—核验—复述

无论用上面哪种方式，最后一步永远是：

1. **定位**：AI 给出的关键事实要能定位到页码/公式/图表/代码行
2. **核验**：引用回到原始来源（论文、官方文档、测试输出）
3. **复述**：最后自己能讲明白，才算真正理解

!!! note "记住"
    能复述，才叫你的；复述不出，只是 AI 的。
