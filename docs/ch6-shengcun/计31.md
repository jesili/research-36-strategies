# 第31计：组会和论文汇报到底应该怎么讲？

> **一句话：汇报不是按章节翻译论文，而是带听众完成一次判断。**

## 为什么

按论文顺序讲 Abstract、Related Work、Method、Experiment，看似完整，却容易让听众在细节中失去主线。汇报的目标是让没读过论文的人知道：问题是否重要、想法是否新、证据是否可信，以及还有什么不足。

## 推荐结构

> Problem → Why → Insight → Method → Evidence → Weakness

- **Problem**：具体研究对象和问题是什么？
- **Why**：为什么值得解决，已有工作哪里不够？
- **Insight**：作者看见了什么关键现象或机会？
- **Method**：核心设计如何利用这个 insight？
- **Evidence**：哪几项结果支撑主要 claim？
- **Weakness**：假设、边界和未回答的问题是什么？

## 一个反例

二十分钟汇报用了十五分钟解释背景和每个模块，关键实验只剩一页。听众知道系统有很多组件，却不知道作者最核心的贡献，更不知道实验是否真的证明了它。

## 应该怎么做

准备前先写一条主线：“因为已有工作存在 X，作者发现 Y，于是提出 Z，并用 E 证明。”每页只承担一个问题，标题尽量写成结论而不是“实验结果”。背景只保留理解主线所需的内容；证据优先讲最能区分方法价值的图表。最后明确给出自己的判断，而不是用“未来工作”代替批评。

## 自检

- [ ] 开场两分钟内是否说清问题与重要性？
- [ ] 能否用一句话说清核心 insight？
- [ ] 每个主要 claim 是否有对应证据？
- [ ] 是否主动说明假设、失败条件与不足？
- [ ] 删掉一页后，主线是否仍然成立？

## 记住

> 听众最后应记住的不是论文目录，而是你对这项工作的判断。
