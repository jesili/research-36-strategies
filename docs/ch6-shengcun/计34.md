# 第34计：什么时候自己解决，什么时候找导师？

<div class="strategy-meta">第六篇 · 生存篇 <span>/</span> 第 34 计</div>

> **一句话原则**
> 技术细节先独立排查，方向与关键判断及时沟通。

## 为什么

什么都问会失去独立解决能力，什么都不问又可能在错误方向上浪费数周。区分问题类型，比机械规定“卡多久再问”更有效。

## 判断边界

- **普通报错**：先查
- **方向判断、关键实验冲突、连续多天无进展**：及时沟通

!!! warning "两种极端都不要"
    不要一分钟一问，也不要一个月不汇报。

## 怎么做

遇到技术问题先记录现象、最小复现、已尝试方法和结果；仍无法解决时带着这些信息求助。方向变化、关键实验冲突、伦理或安全风险、连续多日没有推进判断时，尽早沟通，并带上证据与自己的备选解释。

## 一个例子

环境报错还没读日志就求助；而核心假设连续失败却因担心“没进展”一直隐瞒。前者转移了可独立完成的工作，后者错过及时止损。

## 自检

- [ ] 这是信息问题、技术问题还是方向判断？
- [ ] 我是否完成了基本检索与最小复现？
- [ ] 继续独自处理的机会成本多大？
- [ ] 求助时能否清楚说明现象、分析和需要的帮助？

!!! tip "记住"
    独立不是不求助，而是带着分析在正确时机求助。
